## S5 CORE ENGINE (/core, ships as native, WASM, UniFFI)
5.1 Text model: canonical UTF-8; every span emitted as {utf8:[s,e], utf16:[s,e], scalar:[s,e]} so no client does offset math; grapheme and bidi aware. Tests: emoji ZWJ, surrogates, combining marks, RTL, CRLF, tabs, NBSP, zero-width chars.
5.2 Pipeline: detect locale/script -> segment (paragraph, sentence, word; unicode-segmentation + abbreviation table) -> structure parse (plain, markdown, html, latex, code-comment extraction, URLs, emails, handles, hashtags, emoji, numbers) -> tokens (POS, lemma, morph) -> layers: L1 spelling | L2 rules | L3 ML GEC/rerank | L4 style + readability + tone | L5 LLM assist (async, opt-in) -> merge, dedupe, resolve overlaps by priority and confidence -> apply goals, org style guide, user prefs (ignored rules, dictionary) -> stream suggestions.
5.3 Incremental: sentence-hash cache, dirty-region expansion +-1 sentence, cancellation tokens, document version stamps, drop stale results. L1 to L4 deterministic (same input + settings => same output). LLM outputs cached by (hash, prompt_version, model).
5.4 Suggestion contract (JSON Schema is source of truth; generate TS/Kotlin/Swift): id, rule_id, category(correctness|clarity|engagement|delivery), subcategory, severity(1-3), span{utf8,utf16,scalar}, original, replacements[{text, confidence, kind(replace|delete|insert|rewrite)}], explanation{short, long, examples[]}, flags{autofix_safe, needs_context, style_guide, user_rule}, source(rule|model|llm), doc_version, locale, goals_applied[], provenance(own|oss:<id>), telemetry_class(none).
5.5 Rule DSL (YAML): id, locale, category, subcategory, severity, pattern (token sequence: text|lemma|pos|regex|case|optional|negate|gap), antipatterns, message template, suggestion templates (token refs + inflection fns), examples (>=3 positive, >=3 negative), tags, provenance. Rule CI: compile all, run examples, run false-positive corpus on public-domain text; budget: severity-3 rules <=0.5 FP per 1000 words, overall <=1.5; duplicate and overlap lint; taxonomy coverage report. Targets: 300 rules at M1; 1500+ by M10 (grammar ~600, spelling/confusables ~400, punctuation ~250, clarity/style ~300, inclusive/tone ~150). Rules are authored originally; LLM-assisted authoring allowed only with human-checkable tests per rule.
5.6 Spelling: FST dictionary per locale (en-US, en-GB, en-CA, en-AU, en-IN), frequency-ranked; candidates by edit distance + keyboard adjacency + phonetic keys; context rerank with n-gram/LM; compounds, hyphenation, casing, camelCase/snake_case in code mode; proper-noun heuristics; user and org dictionaries; dictionary licenses logged.
5.7 ML layers (all optional, offline-capable): (a) lightweight GEC tagger/ranker in ONNX, int8, runs on desktop, Android, iOS, WASM; model packs downloadable with checksums. (b) tone/formality multi-label classifier (distilled). (c) AI-likelihood features. DATA LICENSE GATE: only datasets passing docs/legal/DATASETS.md review; many GEC corpora are research-only, so default plan = synthetic error injection on public-domain/CC0 text + permissive corpora + own annotation. Every model gets a model card (data, license, metrics, limits, fairness slices). Eval: ERRANT-style F0.5 on license-clean sets, latency, memory, FP rate, per dialect, per genre, non-native-writer slice.
5.8 Readability and score: Flesch Reading Ease, FK grade, Gunning Fog, SMOG, Coleman-Liau, ARI; reading time 238 wpm, speaking 150 wpm; vocabulary richness. Score 0-100 = 100 minus weighted per-100-word penalties by category and severity, bounded, goal-conditioned; formula documented in-app; original methodology.
5.9 Tone taxonomy (original, 24 labels): confident, assertive, direct, firm, friendly, warm, appreciative, optimistic, joyful, enthusiastic, curious, analytical, neutral, formal, informal, respectful, empathetic, apologetic, concerned, cautious, urgent, persuasive, impatient, dismissive. Output top-3 with confidence; optional per-sentence heatmap; linked to Goals.
5.10 LLM gateway: adapters for NVIDIA NIM (OpenAI-compatible), Google Gemini, OpenAI, Anthropic, any OpenAI-compatible local endpoint (Ollama, llama.cpp server, vLLM); routing by capability, latency, cost with failover; streaming SSE/WS; cancellation; per-user and per-org budgets; encrypted content-hash cache with short TTL; prompt registry (YAML: id, version, task, input schema, output JSON schema, safety notes, eval cases). Tasks: rewrite, tone-shift, shorten, expand, simplify, compose, reply, ideate, summarize, outline, translate, paraphrase, proofread, reader-reactions, grade, domain-review, claim-extract, citation-query, chat. Guardrails: user text is untrusted data inside delimiters, never instructions; no tools reachable from analysis prompts; JSON-schema validation + bounded retry; PII-safe logging; prompt-injection suite (web pages, emails, PDFs, docs).
5.11 Optional on-device LLM (desktop GGUF via llama.cpp; Android and Apple platform runtimes) behind capability checks; never required.
5.12 Interfaces: CLI (nw check, nw rules test, nw bench), WASM (Worker-friendly, SIMD when available, <=3 MB gz), UniFFI (Kotlin, Swift), direct crate use in Tauri, lsp-core.
